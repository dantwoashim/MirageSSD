# MirageSSD 0.1.3 Windows preview

The setup window now supports sign out, sign in, switching Google accounts,
and updating or reinstalling an existing installation. The Start menu also
has an account-management shortcut.

Reinstall replaces the installed binaries even when the drive was mounted,
preserves the recorded drive letter and cache location, and checks pending
uploads before and after stopping the mount. Account changes stage and protect
the new login before activating it. Failed authorization retains the old login.
Switching accounts retains the previous clean cache and Windows attributes in
a `retained-account-*` directory rather than exposing them to the new account.
Uninstall retains account ownership alongside cached data and credentials.

The writable-drive package adds opt-in file preparation through the mounted
provider. Its rclone provider remains `v1.75.0-miragessd2`.

The separate native immutable-repository engine includes adjacent-slot read
coalescing, aligned scratch-buffer reuse, batched arena placement, bounded
shared fetches, and readiness checks. Synthetic measurements are documented
in `docs/experiments/page-geometry-2026-09-14.md`; they are not Google Drive
throughput measurements or a promised speedup for the writable-drive package.

## Review fixes

- Prevent setup from reporting success without replacing a mounted installation.
- Serialize account and installer operations; disable automatic restart during changes.
- Reject dirty, malformed, and unknown upload metadata.
- Stage credentials separately and retain old-account cache and attributes.
- Report reconnect failure instead of claiming that the drive will appear shortly.
- Retain ownership information through uninstall and reinstall.
- Drain account-status output asynchronously so the timeout can take effect.
- Complete a newly owned fetch flight if a page becomes resident during admission.
- Reject coalesced reads whose leases belong to a different arena.
- Update rustls to 0.23.45 for RUSTSEC-2026-0285.

## Verification boundary

Local Windows verification includes workspace formatting, strict Clippy,
the workspace tests, and a rebuilt native adapter passing 100,000 random byte
comparisons on a real mounted volume. Four explicitly ignored release/hardware
tests, including the 72-hour endurance gate, are not claimed as passed.

Fourteen installer/account lifecycle scenarios execute the actual PowerShell
scripts against disposable files with simulated Google authentication and
Windows task/volume integration. They cover fresh installation, mounted
reinstallation, uninstall/reinstallation, rejected upload states, failed
authorization, account switching, logout, and reconnect. Prefetch and platform
capability regression scripts also pass.

The EXE's `--verify-only` check verifies the embedded payload and prerequisites;
it does not install, complete Google sign-in, or prove a clean-machine install.
Fresh-machine installation, real cross-account OAuth, Windows sign-out/sign-in,
and endurance need separate live validation. This remains an unsigned preview.
