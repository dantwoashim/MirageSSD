# MirageSSD 0.1.17 Windows preview

Avoids a kernel-cache deadlock during large copies into writable drives.

The previous host enabled WinFsp kernel data caching on all mounts. The bundled
WinFsp 2.1 driver has a confirmed cached-write deadlock under memory pressure:
the writer waits for cache space while holding the lock needed to flush that
space. See the [upstream diagnosis and fix](https://github.com/winfsp/winfsp/pull/677).
This matches the reported large-copy hang and machine freeze; no kernel dump
from the affected machine was available to confirm its exact blocked stack.

Writable mounts now use a finite file-info timeout, which bypasses that kernel
data-cache path on the existing driver. Writes reach MirageSSD's local journal
admission before completing. Immutable mounts retain kernel read caching.
Writable-mount reads may have lower throughput because they require user-mode
callbacks, while the engine and backing-file caches remain available.

Copy-tool allocation requests no longer extend EOF or force a journal seal.
Allocation shrink below EOF still truncates. File information and append bounds
refresh from the engine so concurrent handles do not reuse stale sizes after
metadata expiry.

Validation includes a regression that fails against the shipped 0.1.16 host:
an ordinary buffered write must reach the journal before returning, even before
flush or close. A real mounted CopyFileEx test copies 96 MiB across three
production segments, flushes, remounts, and compares the complete BLAKE3 hash.
The mounted gate also checks allocation growth leaves EOF unchanged and an
offline full journal returns ERROR_DISK_FULL promptly with earlier data intact.
This deliberately avoids forcing the development machine into kernel memory
exhaustion; it verifies that the affected cache path is bypassed.

Local checks passed: formatting, strict workspace Clippy, 645 workspace tests
(7 ignored), 26 UI tests and the production UI build, the capability inventory,
and 17 device-lifecycle scenarios. The release includes fixes for two existing
CI blockers: Windows-only code triggering Linux lints, and expected failure
cases leaving a nonzero exit status after a successful lifecycle test.

Existing local staging limits and cloud-publication behavior still apply. A
copy is not evidence that its data has finished uploading. No storage-format
migration or deletion of existing application data is introduced.

Install the update to replace and remount the filesystem host. This remains
an unsigned preview.
