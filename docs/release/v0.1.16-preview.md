# MirageSSD 0.1.16 Windows preview

Corrects the management-app installer's service replacement during upgrades.

The 0.1.15 package ran `net stop`, a process-wide `taskkill`, and `sc delete`
before MSI validation, ignored their results, and removed the previous product
before the rollback transaction. A failed stop or outstanding service handle
could leave setup trying to replace a service still marked for deletion. Failure
could also leave the previous installation removed.

This package uses MSI's elevated service actions to stop and remove an existing
or orphaned registration before installing the replacement. Service operations
use bounded waiting. Removal of the previous product is inside MSI's rollback
transaction. Restart Manager handles open application files; setup no longer
force-kills every process with a matching executable name.

The build now checks the compiled MSI's upgrade action order, service-control
flags, absence of external cleanup commands, and ordinary-uninstall safety guard.
The shipped 0.1.15 MSI fails this check; the corrected package passes.

Windows CI now also includes a disposable-machine test for a running-service
upgrade, a deferred failure that must roll back to the running previous product,
and retention of application data through upgrade and uninstall. This new
elevated test has not been run in the local, non-administrator session.

Local validation: formatting, strict workspace Clippy, 644 passing workspace
tests (7 ignored), the rebuilt debug WinFsp host's mounted-volume tests,
26 passing UI tests and production UI build, capability inventory, and WiX MSI
validation. The new PowerShell integration harness passes syntax validation;
its elevated scenarios still require CI execution.

Repository metadata, caches, credentials, and remote files are retained. No
storage-format migration is introduced. If Windows requests a restart because
an earlier failed setup left a service pending deletion, restart before retrying;
do not erase application data as an installation workaround.

The reported stall on the other PC has not been reproduced directly. Package
validation checks the authored lifecycle, not a completed elevated upgrade
or rollback on that PC. This remains an unsigned preview.
