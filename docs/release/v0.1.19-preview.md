# MirageSSD 0.1.19 Windows preview

Faster uploads, much faster reads of files that only live in Drive, and two
fixes for problems that only showed up with a real game on a small cache.

I installed Genshin Impact through a managed drive on my laptop: about 76 GiB
of gameplay data on D:, and the cutscenes, voice and event audio (about
62 GiB) on a MirageSSD drive with a 4 GiB local budget. These are the things
that broke or crawled.

Uploads went out in fixed 64 MiB batches, two 32 MiB objects at a time, and
each batch had to finish before the next one started. On my connection that
published about 3 MB/s, around a third of what the uplink could carry. The
batch size now follows the measured upload rate, aiming for about 45 seconds
per batch, between 64 MiB and 256 MiB. Slow links behave exactly as before;
on mine the same upload ran at 7-9 MB/s.

Reading a file whose local copy had been evicted fetched its 4 MiB frames one
at a time and downloaded the whole 32 MiB segment before returning the first
byte, so video and voice files read at 1-2 MiB/s and took 4-15 s to start.
Frames are now fetched in parallel and split across several connections, the
requested bytes come back as soon as their frames arrive, and the rest of the
segment plus the next two are brought back in the background. Cold reads now
run at about 4-7 MiB/s. The first byte still takes a few seconds on my
connection because every Drive request is slow to start, so files that need
to open instantly are still better kept on the local disk.

Deleting or replacing a file did not give its local bytes back until the drive
was remounted. With a small budget, deleting a few gigabytes was enough to
make every later write wait and then fail with disk full. Deleted and replaced
files now release their local payloads straight away, under the same rule as
compaction: only payloads no other file still refers to, and only after the
change is durable.

Large folders were cut off after the first page of a listing, in Explorer,
`dir` and everything else, when their names contained capital letters,
because the continuation marker was compared against case-folded keys.
Listings now page through the whole folder.

Local checks passed: formatting, strict workspace Clippy, 678 workspace tests
(11 ignored) including the mounted WinFsp gates, 60 UI tests and the
production UI build.

A copy is still not evidence that its data has finished uploading. Install
the update to replace and remount the filesystem host. This remains an
unsigned preview.
