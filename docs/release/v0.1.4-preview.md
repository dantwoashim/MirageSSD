# MirageSSD 0.1.4 Windows preview

Fixes recovery and removal after interrupted setup.

- Setup owns its PowerShell and CLI worker processes. Force-closing setup
  terminates those workers and releases their operation mutex and file handles.
- A Cancel operation button stops an in-progress install or account action.
  The user's browser is launched outside the installer worker job.
- Uninstall support and the installation record are written before sign-in.
  Incomplete installations offer Repair installation and Uninstall.
- Recover interrupted setup closes orphaned workers from the previous EXE
  when their original setup parent is gone. Active setup windows are excluded.
- The new EXE can uninstall an older partial installation even if its manifest
  or installed uninstall script was never written. Legacy launchers provide
  the recorded drive/cache paths; matching legacy startup tasks are stopped.
- Binaries are staged before replacement. Account and installation records
  use atomic replacement. A failed uninstall retains its Settings entry.

On the affected PC, close other setup windows and open this new EXE. Choose
**Recover interrupted setup**, then **Repair installation** or **Uninstall**.
Do not delete the cache as a way to reset setup: it may hold pending uploads.
Removal retains cached data, account credentials, cloud files and shared WinFsp.

Validation: 16 lifecycle scenarios, real force-termination of the setup wrapper
during a simulated login in the actual installer script, worker/file-lock/mutex
cleanup, successful retry, explicit cancellation, legacy orphan-process recovery,
and CLI regression tests. Google authentication and task/volume integration in
these installer tests are simulated. Recovery on the reported remote PC and
real cross-account sign-in have not been observed. This remains unsigned preview
software; the storage engine and provider are unchanged from 0.1.3.
