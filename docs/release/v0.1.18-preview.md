# MirageSSD 0.1.18 Windows preview

Faster small-file work, far fewer Drive requests, and a desktop app that is
organised around your drives.

The app now opens in its own window instead of a browser tab, falling back to
the default browser when Edge is not available. Each drive has one page with
its connection, upload progress, how much of the cache disk MirageSSD is
using, pinned folders, folder offload, cache relocation and free-up-space.
Settings and Help have their own pages, and repository tools only appear when
a repository exists. The tray responds immediately, uses the MirageSSD icon,
and reports the result of free-up-space and diagnostics.

Small-file operations no longer pay for several full disk syncs each. Managed
drives group metadata commits and make them durable within about 250 ms, the
same trade NTFS makes. Operations stay atomic and ordered: a crash or power
loss can lose the last fraction of a second of work, but does not leave
half-written files. FlushFileBuffers still waits until the file is on disk,
and local payloads are only removed after the state that allows it is
durable. Setting `MIRAGE_DURABILITY=strict` in the filesystem host's
environment restores per-operation durability.

Reads no longer hold the engine-wide lock while a payload file is opened and
scanned, and open payload files are reused. On my test machine (i5-1135G7,
NVMe, Defender on) a mounted drive went from about 34 to about 90 small-file
creates per second, deletes from about 150 to about 415 per second, rename
from 8.9 to 3.8 ms, and random 4 KiB reads from about 220 to about 110 µs.
Large sequential writes went from 260-315 to 340-370 MiB/s. These are
indicative numbers from one machine, not a guarantee.

Drive allows roughly three write requests per second per account, so
uploading every small file as its own object meant small files reached Drive
slowly and stayed in the local cache meanwhile. Files up to 4 MiB are now
uploaded together in encrypted objects of up to 16 MiB. Each file is still
sealed and verified on its own, a damaged file does not hold back the rest of
its pack, and reads fetch only the bytes they need. 500 small files now
become about 5 Drive objects instead of 500. Larger files are uploaded
individually as before. Packing is covered by tests against the local object
backend.

Two metadata migrations are added: a durability barrier record and the offset
of each file inside its pack. Existing data is migrated in place and nothing
is deleted. Earlier versions do not understand packed uploads, so going back
to an older version after 0.1.18 has uploaded files is not supported.

The docs, website and installer text now describe the managed drive as it
works: a local journal and cache, encrypted remote objects, a local cache
that MirageSSD does not encrypt, and drive keys that stay on this PC.
`MIRAGE_FS_TRACE` on `mirage-fs.exe` writes a per-callback timing breakdown
for performance work.

Local checks passed: formatting, strict workspace Clippy, 666 workspace tests
(11 ignored) including the mounted WinFsp gate, the engine suite again in
strict durability mode, 60 UI tests and the production UI build.

A copy is still not evidence that its data has finished uploading. Install
the update to replace and remount the filesystem host. This remains an
unsigned preview.
