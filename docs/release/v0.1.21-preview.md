# MirageSSD 0.1.21 experimental preview

Games now offers a real managed Genshin installation or read-only reuse of an
existing installation. The installer contains Mirage's integration code, not
game assets. Setup acquires the current global publisher generation and the
selected English, Japanese, Korean or Chinese voice manifest over authenticated
publisher HTTPS. Bounded decoding and publisher checksums validate the manifest;
native files are reconstructed from verified CDN chunks and checked as complete
files before publishing the generation.

Executables, libraries, anti-cheat components, configuration and writable title
data remain on ordinary local storage. The block, audio and video subtrees use
the read-only native filesystem. The managed installation is separate from any
connected original. Original bytes remain unchanged and count in the displayed
physical footprint; connecting does not immediately reclaim the original game.

The interactive-user session helper survives closing the desktop window. It
tracks executable paths, process creation identities and owned process handles
through launcher handoff. It enables learning only for the observed game PID,
then drains its source before exclusive chunk cleanup. Source ownership and a
durable journal prevent simultaneous launch, maintenance and cleanup. A failed
deletion stays pending and is retried before remount. Recovery never selects an
unrelated Mirage volume by process name alone.

Balanced keeps the prepared launch set and clears other owned chunks after
exit. Disposable clears all owned asset chunks while preserving native files,
user data, originals and bounded generation-specific access history. The next
session prepares a byte-bounded set ranked by observed frequency, recency and
read cost. During play, demand LRU, pins and free-space pressure reclaim bound
owned payloads. Live predictive prefetch is not implemented.

Maintenance stages a replacement native generation and keeps the active one
recoverable on failure. Known writable Persistent and screenshot directories
are preserved without overwriting newly verified publisher files. The desktop
can change retention, select the previous generation or explicitly retire only
its recorded native payloads. Retirement preserves user/unknown files and
disables rollback. Another update requires retiring the previous generation,
preventing silent accumulation of native rollback copies.

The game card separates native allocation, owned cache/metadata, imported
originals, temporary/rollback allocation and available volume space. Virtual
logical size is displayed separately. Ordinary files use allocation information;
sparse/compressed files use their actual allocated data size. Installation and
maintenance reserve native allocation rounding, overlapping generations, the
cache allowance and bounded staging before starting work. The free-space floor
covers filesystem metadata overhead. Native game/user-data writes and unrelated
applications remain outside Mirage's write interception and may require more
space; the storage allowance is an admission check, not a filesystem quota.

The preview uses the acquired publisher-native executable for direct launch.
Full HoYoPlay installation/repair integration, anti-cheat compatibility, actual
fresh-title launch, future publisher patch behavior and gameplay smoothness
remain separate acceptance gates. No performance or storage-saving guarantee is
made. Publisher endpoints and representation formats can change; incompatible
metadata fails closed and leaves the installed generation recoverable.

Verification evidence and its limits are recorded in
[the implementation checklist](../proposals/2026-10-genshin-managed-install-progress.md).
Public release publication remains a separate step; this package is unsigned.
